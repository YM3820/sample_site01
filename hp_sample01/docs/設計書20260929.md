# ボタン操作アニメーション機構 設計書

作成日: 2026-09-29  
対象メモ: `docs/memo20260929.txt`  
参考サイト: [第45回 北浦和阿波おどり](https://kitaurawa.or.jp/)

## 1. 目的

参考サイトの視覚表現を分析し、ボタンの状態変化が利用者に分かりやすく伝わる、再利用可能なアニメーション機構を実装する。

本設計書は、後続の実装担当者が追加判断を最小限にして HTML、CSS、JavaScript を作成できることを目的とする。

## 2. 前提と調査結果

リポジトリには本設計時点で実装ファイルがなく、指定メモだけが存在する。そのため、特定のフレームワークには依存せず、HTML、CSS、Vanilla JavaScript で実装する前提とする。

参考サイトのボタン表現は、主に次の要素で構成されている。

- ページ表示時: CTA が順番に拡大しながら現れる。
- ホバー時: ボタンが少し上に移動して拡大し、影が強くなる。
- ホバー中: 半透明の光沢が左から右へ通過する。
- 押下中: ボタンがわずかに縮み、押した感触を表現する。
- 主要 CTA: 初期表示アニメーション完了後、弱いパルス状の発光を繰り返す。
- `prefers-reduced-motion: reduce` の場合: 不要な動きを止める。

なお、参考サイトの通常ボタンにはクリック地点から広がるリップルはない。火の粉や画面全体の演出は、エンブレムを複数回タップした場合の別機能である。本設計では、通常の操作フィードバックと派手な演出を混同せず、後者は明示的に指定したボタンだけで使用する。

## 3. スコープ

### 3.1 対象

- リンク型ボタンと `button` 要素の共通スタイル
- 通常、ホバー、フォーカス、押下、無効、処理中の各状態
- ページ表示時の CTA 登場アニメーション
- 主要 CTA の控えめな発光
- 任意で有効化できるクリック時のパーティクル演出
- マウス、タッチ、キーボード操作
- モーション低減設定への対応

### 3.2 対象外

- 参考サイト固有の画像、ロゴ、文章、配色の複製
- 画面全体を揺らす演出や、複数回タップによる隠し機能
- WebGL、Canvas、外部アニメーションライブラリ
- ボタン押下後に実行される業務処理そのもの

## 4. 設計方針

1. 基本的な状態表現は CSS だけで実装する。
2. JavaScript は、登場アニメーション完了後の状態移行と、任意のパーティクル生成に限定する。
3. リンク遷移やフォーム送信をアニメーション待ちで遅延させない。
4. キーボードの Enter または Space で操作した場合も、マウス操作と同じ結果にする。
5. 装飾要素は `pointer-events: none` とし、クリック判定を妨げない。
6. `transform` と `opacity` を中心に使用し、レイアウト再計算を抑える。
7. 色、時間、イージングは CSS カスタムプロパティに集約する。

## 5. UI仕様

### 5.1 ボタン種別

| 種別 | クラス | 用途 | 表現 |
|---|---|---|---|
| Primary | `.motion-btn--primary` | ページ内で最重要の操作 | 塗りつぶし、白文字、発光あり |
| Secondary | `.motion-btn--secondary` | 補助操作 | 枠線、透明背景、発光なし |
| Quiet | `.motion-btn--quiet` | 優先度の低い操作 | 背景なし、影を弱くする |

共通クラスは `.motion-btn` とする。リンクの場合も同じクラスを使用する。

```html
<a class="motion-btn motion-btn--primary" href="/next.html">
  詳細を見る
</a>

<button class="motion-btn motion-btn--secondary" type="button">
  閉じる
</button>
```

### 5.2 状態別の見た目

| 状態 | 条件 | 表現 |
|---|---|---|
| Default | 操作前 | `scale(1)`、標準の影 |
| Hover | `:hover` かつ精密ポインター | `translateY(-4px) scale(1.045)`、影を強調、光沢を走らせる |
| Focus | `:focus-visible` | 2px の明確なアウトラインと 3px 程度の余白 |
| Pressed | `:active` | `translateY(-1px) scale(.98)` |
| Disabled | `:disabled` または `aria-disabled="true"` | 不透明度 0.5、影とアニメーションを停止、禁止カーソル |
| Loading | `.is-loading`、`aria-busy="true"` | 二重操作を防止し、ラベル横にスピナーを表示 |

押下表現は 80〜140ms で認識できる軽い変化とし、クリック後の処理を遅らせない。

### 5.3 登場アニメーション

- 対象コンテナ: `[data-motion-group]`
- 対象要素: コンテナ直下の `.motion-btn`
- 開始値: `opacity: 0; transform: scale(.6) translateY(10px)`
- 65% 時点: `opacity: 1; transform: scale(1.06) translateY(0)`
- 完了値: `opacity: 1; transform: scale(1) translateY(0)`
- 時間: 600ms
- イージング: `cubic-bezier(.34, 1.56, .64, 1)`
- 要素間の遅延: 120ms
- 実行回数: 初回表示時の1回のみ

画面下部のボタンにも適用する場合は、`IntersectionObserver` で初めて表示領域に入ったときに `.is-entered` を付与する。ヒーロー領域の CTA はページ読み込み直後に開始してよい。

### 5.4 ホバー光沢

`.motion-btn::after` に光沢用の疑似要素を配置する。

- 幅: ボタン幅の約40%
- 背景: 透明 → 半透明の白 → 透明の線形グラデーション
- 初期位置: 左端より外側
- ホバー時: 600ms で右端より外側へ移動
- 疑似要素には `pointer-events: none` を設定する。
- `overflow: hidden` でボタン外の光沢を非表示にする。

タッチ端末ではホバーが残留する場合があるため、`@media (hover: hover) and (pointer: fine)` の内部だけで有効化する。

### 5.5 Primary の発光

Primary ボタンは、登場アニメーション完了後に `.is-pulse-ready` を付与して発光を開始する。

- 周期: 2.2秒
- 変化: `box-shadow` の外周を 0px から 12px まで広げ、同時に透明にする。
- ホバー中: 発光を一時停止する。
- 処理中または無効状態: 発光を停止する。
- 常時発光させる Primary は、1画面につき原則1個までとする。

登場アニメーションと発光が同じ `animation` プロパティを競合しないよう、`animationend` で登場完了を確認してから発光クラスを追加する。

### 5.6 任意のクリック演出

`data-motion-effect="burst"` を持つボタンだけ、クリック時に短い放射状パーティクルを表示できる。

```html
<button
  class="motion-btn motion-btn--primary"
  type="button"
  data-motion-effect="burst"
>
  お祝いする
</button>
```

仕様は次のとおり。

- 発火イベント: `click`
- 発生原点: ポインター操作ではクリック座標、キーボード操作ではボタン中央
- 要素数: PC 16個、幅700px未満は10個
- 継続時間: 450〜750ms の範囲でランダム
- 移動距離: 24〜72px
- サイズ: 3〜7px
- 色: UIテーマ内のアクセントカラーを2〜3色使用
- 実装: `span` を `document.body` 直下へ一時生成し、CSS変数 `--dx`、`--dy`、`--duration` を渡す。
- 後始末: `animationend` で削除し、イベント欠落対策として1秒後にも削除を試みる。
- 多重実行制御: 同一ボタンでは300ms以内の連打による追加生成を抑制する。
- ナビゲーションリンク: 演出のために `preventDefault()` しない。遷移先で演出が見えなくても正常とする。

この演出は意味のある完了操作、キャンペーン、遊びのあるコンテンツに限定し、全ボタンへ一括適用しない。

#### fireworks（より派手な花火演出）

`data-motion-effect="fireworks"` を持つボタンは、クリック位置から花火を打ち上げ、画面全体に開かせる。

- 構成: 押した位置での小さな破裂 ＋ 打ち上げ花火 PC 8発、幅700px未満は5発（110〜190ms 間隔）
- 破裂位置: 画面幅の12〜88%、高さの10〜42% の範囲でランダム
- 種類: 牡丹（球状）、輪、柳（長く垂れる）、二重輪をランダムに選び、破裂時に白い閃光を重ねる
- 色: 赤・金・橙・水色・緑・桃・紫・白の多色
- 実装: 全画面固定の `canvas.motion-fireworks`（`pointer-events: none`、`aria-hidden`）を1枚だけ生成し、`requestAnimationFrame` で描画する。描くものがなくなった時点で canvas を削除する。
- 上限: 火花は同時に最大1200個
- 多重実行制御: 同一ボタンでは500ms以内の連打を抑制する
- モーション低減・強制カラー時は表示しない。`destroy` 時は描画を停止して canvas を削除する。

## 6. DOMインターフェース

| 属性またはクラス | 必須 | 説明 |
|---|---:|---|
| `.motion-btn` | 必須 | 共通のボタン動作を有効化 |
| `.motion-btn--primary` など | 必須 | 表示種別 |
| `[data-motion-group]` | 任意 | 子ボタンの登場アニメーションをまとめる |
| `[data-motion-effect="burst"]` | 任意 | クリック時パーティクルを有効化 |
| `[data-motion-effect="fireworks"]` | 任意 | クリック時の打ち上げ花火演出を有効化 |
| `.is-entered` | 自動 | 登場アニメーション開始済み |
| `.is-pulse-ready` | 自動 | Primary の発光開始可能 |
| `.is-loading` | 呼出側 | 非同期処理中 |
| `aria-busy="true"` | 呼出側 | 支援技術へ処理中であることを通知 |
| `disabled` / `aria-disabled` | 呼出側 | 操作不可状態 |

JavaScript が無効でも、ボタン本体、リンク遷移、ホバー、フォーカス、押下の CSS 表現は利用できること。

## 7. 処理設計

### 7.1 初期化

```text
DOMContentLoaded
  ├─ motion低減設定を取得
  ├─ data-motion-group を列挙
  │    └─ 対象を表示済みにする、または IntersectionObserver に登録
  ├─ Primary の animationend を監視
  │    └─ entrance完了後に is-pulse-ready を付与
  └─ burst指定ボタンへ click リスナーを登録
```

初期化関数は複数回呼ばれてもリスナーを重複登録しないよう、対象要素に `data-motion-initialized="true"` を付与する。

### 7.2 クリック時

```text
click
  ├─ disabled / aria-disabled / loading なら終了
  ├─ motion低減設定が有効なら終了
  ├─ 直前の実行から300ms未満なら終了
  ├─ 発生原点を決定
  ├─ パーティクルを生成
  └─ animationend またはタイムアウトで削除
```

クリック処理を中心にすることで、タッチ後に合成される `click` と `touchend` の二重発火を避ける。`pointerdown` は座標の保存だけに使用してもよいが、演出開始には使用しない。

### 7.3 処理中状態

非同期処理を行うボタンでは、呼出側が次の順で状態を変更する。

1. `.is-loading` と `aria-busy="true"` を追加する。
2. `button.disabled = true` にして二重送信を防ぐ。
3. 非同期処理を実行する。
4. 成否にかかわらず `finally` で上記状態を解除する。

リンク型ボタンを操作不可にする場合は、`aria-disabled="true"` を設定し、クリックハンドラーで遷移を停止する。CSSだけで無効化を表現してはならない。

## 8. CSS設計

### 8.1 デザイントークン

```css
:root {
  --motion-accent: #c1272d;
  --motion-accent-rgb: 193, 39, 45;
  --motion-on-accent: #fff;
  --motion-focus: #1f3a5c;
  --motion-fast: 120ms;
  --motion-normal: 300ms;
  --motion-enter: 600ms;
  --motion-ease-out-back: cubic-bezier(.34, 1.56, .64, 1);
}
```

実装先に既存のデザイントークンがある場合は、上記を新設せず既存値へマッピングする。

### 8.2 レイヤー分割

- Base: サイズ、余白、文字、枠線
- Variant: Primary、Secondary、Quiet
- State: hover、focus-visible、active、disabled、loading
- Motion: enter、shine、pulse、burst
- Accessibility: reduced-motion、forced-colors

### 8.3 モーション低減

```css
@media (prefers-reduced-motion: reduce) {
  .motion-btn,
  .motion-btn::before,
  .motion-btn::after,
  .motion-particle {
    animation: none !important;
    transition-duration: 0.01ms !important;
  }
}
```

低減設定時も、色、枠線、フォーカスリングによる状態差は維持する。登場前の `opacity: 0` が残らないよう、必ず `opacity: 1; transform: none` を指定する。

## 9. JavaScript API案

外部から必要な場合だけ、次の最小APIを公開する。

```js
ButtonMotion.init(root = document)
ButtonMotion.setLoading(element, isLoading)
ButtonMotion.destroy(root = document)
```

- `init`: 未初期化の対象だけを設定する。
- `setLoading`: クラス、`aria-busy`、`disabled` を一括更新する。
- `destroy`: リスナーと Observer を解除し、生成途中のパーティクルを削除する。

単純な静的サイトで外部呼び出しが不要なら、即時関数内に閉じてもよい。

## 11. アクセシビリティ要件

- `div` をボタン代わりに使用しない。
- 画面遷移は `a`、画面内操作は `button` を使用する。
- キーボードフォーカスを常に視認できるようにする。
- `:focus` を無条件に消さない。
- 色だけで押下、無効、処理中を表現しない。
- クリック領域は原則として高さ44px以上とする。
- パーティクルは装飾として扱い、アクセシビリティツリーへ追加しない。
- 状態変化を通知する必要がある業務処理では、別途 `aria-live` 領域へ結果を表示する。
- `prefers-reduced-motion` をページ読み込み時だけでなく、可能なら `matchMedia` の変更イベントでも反映する。

## 12. 性能・安全性要件

- 同時に存在するパーティクルは最大40個とする（fireworks は canvas 描画のため別枠で火花最大1200個）。
- パーティクルの DOM は必ず削除し、再利用しない。
- スクロールやリサイズの高頻度イベントを新設しない。
- レイアウト変更を起こす `top`、`left` の連続アニメーションは避け、`transform` で移動する。
- `will-change` は常設せず、必要な短時間だけ使用する。
- ユーザー入力から見た応答開始は100ms以内を目標とする。
- JavaScript エラーが起きても、本来のリンク遷移やフォーム操作を妨げない。

## 13. テスト項目

### 13.1 機能

- Primary、Secondary、Quiet が仕様どおり表示される。
- マウスホバーで浮上、影、光沢が動作する。
- 押下中に縮小し、離すと元へ戻る。
- CTA が指定順で1回だけ登場する。
- Primary の発光が登場完了後に開始する。
- burst 指定ボタンだけにパーティクルが表示される。
- 連打してもパーティクル数が上限を超えない。
- Loading 中に二重操作できない。
- JavaScript 無効時もリンクとボタンの基本機能が壊れない。

### 13.2 入力方法

- マウスクリック
- タッチ操作
- Enter キーによるリンク、ボタン操作
- Space キーによるボタン操作
- Tab および Shift+Tab によるフォーカス移動

### 13.3 環境

- Chrome 最新版
- Safari 最新版（iOSを含む）
- Firefox 最新版
- Edge 最新版
- 幅 320px、768px、1440px
- `prefers-reduced-motion: reduce`
- Windows High Contrast / `forced-colors: active`

## 14. 受け入れ条件

1. ホバー、フォーカス、押下、無効、処理中の違いが視覚的に判別できる。
2. 押下後のリンク遷移や業務処理が、演出待ちで遅延しない。
3. タッチ操作でホバー状態が不自然に残らない。
4. キーボードだけですべてのボタンを操作できる。
5. モーション低減設定時に、移動、点滅、パーティクルが停止する。
6. 10秒間の連続操作後も、不要なパーティクル DOM が残らない。
7. 主要ブラウザーでコンソールエラーが発生しない。
8. Lighthouse Accessibility の対象項目で重大な問題がない。

## 15. 実装順序

1. HTML のボタン種別と属性を定義する。
2. Base、Variant、Focus、Active、Disabled の CSS を実装する。
3. 登場、光沢、発光の CSS を追加する。
4. `prefers-reduced-motion` と `forced-colors` を実装する。
5. JavaScript の初期化、発光への引き継ぎを実装する。
6. 任意の burst 演出と後始末を実装する。
7. Loading API と二重操作防止を実装する。
8. 入力方法別、ブラウザー別にテストする。

## 16. 実装時の判断事項

実装前にサイト全体のデザインが決まっている場合は、アクセント色、角丸、影、フォントを既存デザインへ合わせる。未決定の場合は、本設計の値を初期値として使用する。

パーティクル演出は標準機能ではなくオプションとする。要件が「参考サイトの通常 CTA と同じ操作感」に限定される場合は、`data-motion-effect="burst"` の実装を省略してよい。
